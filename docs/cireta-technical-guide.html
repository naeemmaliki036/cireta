Design Principles
  • Thin controllers — endpoints validate + delegate only
  • Service layer holds ALL business logic
  • Repository pattern — DB access abstracted

  • EncryptedString/JSON for all PII at rest

JWT Strategy

TokenTTLStorage
Access JWT15 minMemory / Authorization header
Refresh Token7 dayshttpOnly cookie
BlacklistUntil expiryRedis hash set
Token Rotation
On every refresh: old token invalidated, new one issued. Old hash stored in Redis for remaining TTL to prevent replay attacks.

Sumsub Webhook Validation

kyc/webhook.py — VALIDATE FIRST
import hmac, hashlib def validate_sig(body: bytes, sig: str, secret: str) -> bool: exp = hmac.new( secret.encode(), body, hashlib.sha256).hexdigest() return hmac.compare_digest(exp, sig) body = await request.body() sig = request.headers["X-App-Token"] if not validate_sig(body,sig,SECRET): raise HTTPException(401, ...)
⚠ Critical Security Rule
HMAC validation MUST run BEFORE any processing. Return 401 if invalid. Never process webhook payload before signature check.

Audit Log Guarantee
Every compliance action writes an immutable row to audit_logs. Table is append-only — no UPDATE or DELETE ever issued. Fields: actor_id, action, target_type, target_id, payload JSON, ip_address, created_at.
admin.cireta.com/compliance

Standard Error Format

{ "code": "ERROR_CODE", "message": "Human readable text", "detail": {} // optional } // 400 — validation error // 401 — not authenticated // 403 — insufficient role/kyc // 404 — resource not found // 422 — Pydantic validation fail // 429 — rate limit exceeded // 500 — internal server error
Never expose stack traces
500 errors return generic message only. Full traceback written to structured logs. Sentry captures unhandled exceptions in production.

0x224fa1965b5B8C1428eD5D92E6d04CF5967aE9ac
Deploys VaultImpl + FractionTokenImpl for vested sale mechanics. Manages vesting schedules and tranche releases on-chain.

ONCHAINID Integration

Each KYC-approved investor gets an on-chain identity via ONCHAINID. Claims issued by Cireta's trusted issuer key, stored on identity contract.

// Claim Topics CLAIM_KYC_APPROVED = 1 CLAIM_COUNTRY_CODE = 7 CLAIM_AML_CLEARED = 3 // Web3Service.issue_claim() identity.addClaim( topic, scheme, issuer, signature, data, uri )
Transfer Validation Flow
1. Sender calls token.transfer(to, amt)
2. Hook calls compliance.canTransfer(from,to,amt)
3. Each compliance module checked in sequence
4. Identity registry validates KYC claims for both addresses
5. Transfer executes or reverts with reason
Upgradeability
All platform contracts use OpenZeppelin UUPS proxy. Upgrades require the deployer wallet with a 48-hour timelock enforced on-chain.

CIRETAChapter 14 — Background WorkersPage 16
Chapter 14
Background Workers
Two background processes alongside the API: arq job queue for async tasks and an event listener for on-chain sync (every ~12s).

arq Worker Jobs

Email Notifications
Triggered by: KYC status change, sale finalization, dividend declaration, vesting tranche ready, redemption status change. Uses Resend API with HTML templates.
KYC Processing
After Sumsub webhook: validate HMAC → parse result → update kyc_status + kyc_level → issue ONCHAINID claims → write audit_log → queue email.
AML Screening
Periodic re-screening of existing investors against updated sanctions lists. Triggers compliance freeze on new hits. Every run writes audit_log.
Reconciliation
Reconciles on-chain token balances with DB holdings. Flags discrepancies for review. Also reconciles pending contributions against confirmed tx hashes.

Event Listener (Chain Sync)

Block Polling — 12s interval
Listens for Base events every ~12s. Events tracked: Transfer, TokensClaimed, SaleFinalized, VestingClaimed, RedemptionFulfilled. Updates DB state accordingly.

Worker Config

## apps/api/worker.py from arq import create_pool from arq.connections import RedisSettings class WorkerSettings: functions = [ send_email_notification, process_kyc_result, run_aml_screening, reconcile_balances, ] redis_settings = RedisSettings( host=settings.redis_host ) max_jobs = 10 job_timeout = 300 # 5 minutes
Worker Deployment
Separate Railway service using same Docker image. CMD: arq apps.api.worker.WorkerSettings. Shares PostgreSQL + Redis with the API.

CIRETAChapter 15 — Testing StrategyPage 17
Chapter 15
Testing Strategy
Three-tier pyramid: unit tests for services, integration tests against real test DB, E2E via Playwright (85 tests).

Backend (pytest)

Unit Tests — tests/unit/
Every service method in isolation. External deps (Sumsub, Web3) mocked via pytest-mock. ComplianceMock for compliance logic. Target: 100% service coverage.
Integration Tests — tests/integration/
FastAPI TestClient + real PostgreSQL. Full request → service → DB round-trip. No DB mocks — real migrations applied. Sumsub/Web3 still mocked.
E2E Tests — tests/e2e/
Playwright. 85 tests covering full investor journey: register → KYC → wallet → contribute → claim → portfolio → redemption.
pytest tests/unit/ -q pytest tests/integration/ -q pytest tests/e2e/ -q --headed

Contract Tests (Hardhat)

Hardhat Test Suite
TypeScript tests. Deploy factory → token → run transfer/compliance scenarios → test vesting → test sale flow. Uses Hardhat Network (local Base fork).
cd contracts npx hardhat test npx hardhat coverage

Frontend (Vitest)

Component Tests
Vitest + React Testing Library for all atoms/molecules. Mock API repositories. Assert render, a11y, and event handling.
cd apps/launchpad && npx vitest run cd apps/admin && npx vitest run
⚠ CI Requirement
All 3 tiers must pass before merging to main. Results documented in BUILD_LOG.md. Failing test = blocked merge.
