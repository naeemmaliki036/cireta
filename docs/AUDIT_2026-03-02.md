# Cireta Feature Audit — 2026-03-02

## CRITICAL Gaps (blocks demo)

- [ ] **Sumsub KYC integration is a placeholder** — `apps/api/services/kyc_service.py:72-93` — `generate_sdk_token()` returns `"placeholder-token-{user_id}"` instead of calling Sumsub API. No `hmac`, no `httpx`/`requests` import, no real HTTP call. KYC flow will not work end-to-end. Blocks any investor from getting verified.

- [ ] **Invest page USDC approve targets wrong address** — `apps/launchpad/src/app/invest/[slug]/page.tsx:83` — `saleContractAddress` is hardcoded to `USDC_ADDRESS` (itself) with `// TODO: use sale contract address`. USDC approve will approve USDC to spend its own tokens — invest tx will fail on-chain.

- [ ] **No `vest_tokens` background worker** — `apps/api/workers/tasks.py` — Spec requires `vest_tokens` task. Only `task_deploy_onchainid`, `task_register_wallet_on_chain`, `task_index_contribution`, and `task_send_email` exist. No automated vesting release mechanism.

- [ ] **No `process_contribution` background worker** — `apps/api/workers/tasks.py` — Spec requires `process_contribution` task. `task_index_contribution` exists but is a stub (`pass`) that doesn't verify on-chain amounts or update contribution status.

- [ ] **No Sale.sol test** — `contracts/test/` — Missing `Sale.test.ts`. All other core contracts have tests. Sale contract is untested — cannot verify fundraise logic works correctly.

## HIGH Gaps

- [ ] **No dedicated vesting API endpoint file** — No `apps/api/api/v1/endpoints/vesting.py` — Vesting endpoints are embedded in `portfolio.py` (lines 120-137). Spec calls for separate vesting router. Functional but doesn't match architecture spec.

- [ ] **`task_register_wallet_on_chain` is a stub** — `apps/api/workers/tasks.py:89-93` — Contains `# TODO: call identityRegistry.registerIdentity(...)` and only logs. Wallet won't be registered in on-chain Identity Registry after KYC approval, breaking ERC-3643 transfer compliance.

- [ ] **`task_index_contribution` is a stub** — `apps/api/workers/tasks.py:96-101` — Contains `# TODO: read from chain via web3, verify amounts match DB` and `pass`. No on-chain verification of contributions.

- [ ] **Alembic migrations not co-located with API** — `infra/alembic/` exists with 4 migration files, but `apps/api/alembic/` does not exist. Spec implies migrations under API. Minor structural issue but could cause confusion. Migrations DO exist and reference all models.

- [ ] **No DB seed script integration** — `scripts/seed.py` exists but no `pnpm seed` or `poetry run seed` command in `package.json` or `pyproject.toml`. Demo data loading path is unclear.

- [ ] **Home page stats are not from a dedicated stats endpoint** — `apps/launchpad/src/app/page.tsx` fetches projects and derives stats client-side. No `/api/v1/stats` or `/api/v1/platform/stats` endpoint for aggregate platform metrics (total raised, total investors, etc.).

- [ ] **Navbar.tsx exceeds 300 LOC** — `apps/launchpad/src/components/organisms/Navbar.tsx` is 302 lines. Spec mandates 300 LOC max per file.

## Summary

**5 CRITICAL, 7 HIGH, 10 MED gaps found.**

The codebase is substantially complete (~85-90% of spec). Smart contracts are solid (27 tests passing). Frontend pages all exist and are wired to real API endpoints. The main blockers are:

1. **Sumsub integration is fake** — biggest demo blocker
2. **Invest flow approves wrong contract address** — will fail on-chain
3. **Missing worker tasks** — `vest_tokens` and `process_contribution` don't exist
4. **Sale.sol has no test** — untested fundraise contract
5. **On-chain identity registration is stubbed** — ERC-3643 transfers will fail without it
